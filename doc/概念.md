#### AIV、AICPU、AICORE

在华为昇腾（Ascend）NPU 的达芬奇（DaVinci）架构中，**AIV** 的全称是 **AI Vector（向量运算单元）**。它是 AI Core 内部除矩阵单元外的核心计算组件，专用于处理向量级计算、数据搬运与流程控制。

**📐 1. 架构定位**

- 每个 AI Core 通常集成 **1个 AIC（AI Cube，矩阵计算单元）** + **2个 AIV（AI Vector，向量计算单元）**。

- **分工对比**：

向量计算、逐元素操作、数据格式转换、控制流

激活函数、Norm、Softmax、GEMV、数据打包/解包、算子融合

**⚙️ 2. 核心能力与硬件特性**

- **SIMD 并行执行**：采用单指令多数据流架构，一条指令可同时处理多个向量元素，适合规整数据的高吞吐计算。

- **访存连续性要求高**：AIV 对连续内存访问优化极佳。实际开发中需通过 **Tiling（分块）** 与数据重排，保证 `Load → Compute → Store` 流水线不断流。

- **分支支持弱**：AIV 缺乏硬件级条件跳转与复杂分支预测能力。遇到 `if/else` 或动态循环时，需改用 **无分支（Branch-Free）掩码计算** 或提前在 Host/AI CPU 完成逻辑分发。

- **通信算法承载**：支持将部分集合通信（HCCL）的编排逻辑展开到 AIV 执行。通过环境变量 `HCCL_OP_EXPANSION_MODE=AIV` 可开启，减轻 Control CPU 负担。

**3. 典型应用场景**

- **GEMV（矩阵向量乘）**：大模型解码阶段的核心操作，AIV 版本通过连续访存与任务二次切分，性能可达默认 GEMM 方案的数倍。

- **Elementwise 算子**：ReLU、SiLU、GeLU、Add、Mul 等逐元素计算。

- **归一化与激活**：LayerNorm、RMSNorm、Softmax 的向量级实现。

- **数据预处理/后处理**：BF16/FP16 打包解压、INT8 量化/反量化、张量布局转换（NCHW↔NHWC等）。

- **算子融合**：如 `GEMV + Activation + Bias` 融合，AIV 上融合损耗可控制在 `<2%`。

**💻 4. 开发方式（AscendC）**

- 使用 **AscendC** 语言编程，通过 `GlobalTensor`、`LocalTensor`、`Pipe`、`DataCopy` 等 API 显式管理向量寄存器、片上内存与计算流水线。

- **关键优化点**：

- 保证数据对齐与连续访存

- 避免在 AIV 内写复杂分支逻辑

- 合理设置 `Tiling` 尺寸以匹配向量寄存器宽度

- 利用 `Mask` 机制处理非规整数据

**💡 一句话总结**

> **AIC 是“重型矩阵发动机”，AIV 是“灵巧向量流水线”**。AIV 不擅长跑大矩阵，但负责把数据“理顺、打包、快速加工”，是提升访存效率、实现算子融合与轻量计算的关键单元。
